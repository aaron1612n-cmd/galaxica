@@ tk.err2.screen-distance
Q: TclError: bad screen distance "abc" / expected screen distance but got "abc"
aka: bad screen distance, expected screen distance, width string error, padx error, invalid size value
err: bad screen distance "*"|expected screen distance but got "*"
A: A size option (`width`, `height`, `padx`, `bd`, `x`...) got something that isn't a number or a distance like `"2c"`/`"10p"`. Often a variable holding text (`"200px"`) or the wrong argument order.
see: tk.ref.common-options
```py raises
import tkinter as tk
root = tk.Tk()
tk.Frame(root, width="200px")          # "px" isn't a Tk unit
```
```py
import tkinter as tk

root = tk.Tk()
tk.Frame(root, width=200, height=50, bg="#ffd27a").pack()     # plain numbers = pixels
tk.Frame(root, width="3c", height="1c", bg="#9bd").pack()      # c = cm, i = inch, p = point
root.mainloop()
```

@@ tk.err2.bad-anchor
Q: TclError: bad anchor "middle" (or bad relief / bad side / bad fill style / bad state)
aka: bad anchor, bad relief, bad side, bad fill style, bad state, must be n ne e, must be flat groove, must be top bottom left right, must be none x y both, must be active disabled normal
err: bad anchor "*"|bad relief "*"|bad side "*"|bad fill style "*"|bad state "*"|bad justification "*"|bad orientation "*"
A: The option only accepts certain words, and the message lists them. Copy one exactly (they're lowercase): anchor `n ne e se s sw w nw center`; relief `flat groove raised ridge solid sunken`; side `top bottom left right`; fill `none x y both`; state `normal disabled active` (and `readonly` only for Entry/Spinbox/ttk).
see: tk.relief, tk.label-align
```py raises
import tkinter as tk
root = tk.Tk()
tk.Label(root, text="hi", anchor="middle")
```
```py
import tkinter as tk

root = tk.Tk()
tk.Label(root, text="hi", anchor="center", relief="groove").pack(side="top", fill="x")
root.mainloop()
```
tkinter also has constants for these: `tk.CENTER`, `tk.LEFT`, `tk.BOTH`, `tk.DISABLED`... which avoids typos.

@@ tk.err2.geometry
Q: TclError: bad geometry specifier "300*200"
aka: bad geometry specifier, geometry wrong format, geometry string error, root.geometry error

A: The format is `"WIDTHxHEIGHT+X+Y"` with a lowercase **x** and no spaces: `"300x200"`, `"300x200+50+100"`, or just `"+50+100"` to move. Build it with an f-string from numbers: `f"{w}x{h}"`.
see: tk.geometry

```py raises
import tkinter as tk
root = tk.Tk()
root.geometry("300 x 200")
```
```py
import tkinter as tk

root = tk.Tk()
w, h = 300, 200
root.geometry(f"{w}x{h}+50+100")
root.mainloop()
```

@@ tk.err2.transparent
Q: TclError: unknown color name "transparent" (how do I make a widget's background transparent?)
aka: transparent background, transparent label, transparent widget, see-through label, bg none, label on image transparent background
err: unknown color name "transparent"|unknown color name ""
A: tk widgets can't have see-through backgrounds. Options: put the text **on a Canvas** with `create_text` (it has no background, so the image shows through); give the label the same colour as what's behind it; or on Windows only, make one colour of the whole window invisible with `root.attributes("-transparentcolor", colour)`.
see: tk.bg-image, tk.alpha
```py
import tkinter as tk

root = tk.Tk()
c = tk.Canvas(root, width=300, height=150, highlightthickness=0); c.pack()
for y in range(0, 150, 10):
    c.create_rectangle(0, y, 300, y + 10, fill="#ffb000" if y % 20 else "#c23b22", outline="")
c.create_text(150, 75, text="Text with no background", font=("Arial", 16, "bold"), fill="white")
root.mainloop()
```

@@ tk.err2.app-destroyed
Q: TclError: can't invoke "button" command: application has been destroyed
aka: application has been destroyed, cannot invoke command, after destroy, widget after window closed, invoke after destroy
err: can't invoke "*" command: application has been destroyed|cannot invoke "*" command: application has been destroyed
A: Code tried to create or use a widget **after** the window was destroyed: usually code placed after `mainloop()`, an `after` callback still scheduled, or a thread. Do window work before `mainloop()` returns, cancel `after` jobs when closing, and check `winfo_exists()`.
see: tk.err.invalid-command, tk.win.not-responding-close
```py raises
import tkinter as tk
root = tk.Tk()
root.destroy()
tk.Label(root, text="too late")
```
```py
import tkinter as tk

root = tk.Tk()
label = tk.Label(root, text="0"); label.pack()
job = None

def tick(n=0):
    global job
    label.config(text=n)
    job = root.after(50, tick, n + 1)

def close():
    if job:
        root.after_cancel(job)      # stop the loop first
    root.destroy()

root.protocol("WM_DELETE_WINDOW", close)
tick()
root.after(200, close)
root.mainloop()
print("closed cleanly")
```
```text
closed cleanly
```

```py raises
f = tk.Frame(win)

```
```py
import tkinter as tk

root = tk.Tk()
win = tk.Toplevel(root)
tk.Label(win, text="I'm in the second window").pack(padx=20, pady=20)     # parent = win
root.mainloop()
```

@@ tk.err2.callback-exception
Q: "Exception in Tkinter callback" is printed but the window keeps running. What does it mean?
aka: exception in tkinter callback, error in button command, traceback printed window still open, report_callback_exception, show errors in messagebox
err: Exception in Tkinter callback
A: An error happened inside a function tkinter called (a button command, binding, `after`). tkinter prints the traceback and carries on. Read the traceback **below** that line to find the real error. To show such errors to users, override `root.report_callback_exception`.
see: py.read-traceback
```py
import traceback
import tkinter as tk
from tkinter import messagebox

root = tk.Tk()
def show_error(exc_type, exc, tb):
    text = "".join(traceback.format_exception(exc_type, exc, tb))
    print("caught:", exc_type.__name__, exc)
    messagebox.showerror("Something went wrong", str(exc))

root.report_callback_exception = show_error
b = tk.Button(root, text="Divide", command=lambda: 1 / 0); b.pack(padx=40, pady=30)
b.invoke()
root.mainloop()
```
```text
caught: ZeroDivisionError division by zero
```

@@ tk.err2.emoji
Q: TclError: character U+1f600 is above the range (U+0000-U+FFFF) allowed by Tcl
aka: emoji tkinter error, character above range allowed by tcl, unicode emoji label, non bmp character
err: character U+* is above the range (U+0000-U+FFFF) allowed by Tcl
A: Old Tcl/Tk (before 8.6.10 with older Pythons) can't show characters outside the basic range, like most emoji. Upgrade Python (3.8+ installers ship a newer Tk; Tk 9 handles emoji), or strip them: `''.join(c for c in s if ord(c) <= 0xFFFF)`.
see: tk.tk-version
```py
import tkinter as tk

def safe(text):
    if tk.TkVersion >= 8.7:
        return text
    return "".join(ch for ch in text if ord(ch) <= 0xFFFF)

root = tk.Tk()
print(tk.TkVersion)
tk.Label(root, text=safe("Party 🎉 time"), font=("Arial", 16)).pack(padx=20, pady=20)
root.mainloop()
```

@@ tk.err2.wait-visibility
Q: TclError: window ".!toplevel" was deleted before its visibility changed
aka: deleted before its visibility changed, wait_visibility error, grab_set error destroyed, dialog closed too fast
err: window "*" was deleted before its visibility changed
A: `wait_visibility()` (often called just before `grab_set()`) was still waiting when the window got destroyed, e.g. the dialog closed itself immediately or the app quit. Only call it on windows that will be shown, or wrap it in `try/except tk.TclError`.
see: tk.modal
```py
import tkinter as tk

root = tk.Tk()
def open_dialog():
    win = tk.Toplevel(root)
    tk.Label(win, text="Dialog").pack(padx=30, pady=20)
    try:
        win.wait_visibility()
        win.grab_set()
    except tk.TclError:
        pass                   # it was closed before it appeared
root.after(50, open_dialog)
root.mainloop()
```

@@ tk.err2.two-mainloops
Q: My second window doesn't respond / code after mainloop() runs only when I close the window
aka: code after mainloop not running, two mainloops, mainloop blocks, nothing happens after mainloop, second mainloop
A: `mainloop()` doesn't return until the window closes, so code after it waits. Put all setup **before** `mainloop()`, react to things with callbacks/`after`, and call `mainloop()` once, at the very end, on the root only (not on Toplevels).
see: tk.mainloop
```py
import tkinter as tk

root = tk.Tk()

tk.Label(win, text="second").pack(padx=30, pady=20)
root.after(100, lambda: print("callbacks run while the loop is going"))
root.mainloop()                  # ...then ONE mainloop at the end
print("this runs after the window closes")
```

```text
callbacks run while the loop is going
this runs after the window closes
```

@@ tk.err2.image-subsample
Q: TclError: image "pyimage2" doesn't exist after resizing or zoom/subsample
aka: zoom image error, subsample error, image disappears after zoom, resized image blank
A: `zoom()`/`subsample()`/`copy()` return a **new** image object. If you don't keep a reference to that new one, Python deletes it and the label goes blank (or errors). Store it: `label.img = img.zoom(2)`.
see: tk.err.image-gone, tk.img-zoom
```py
import tkinter as tk

root = tk.Tk()
base = tk.PhotoImage(width=20, height=20); base.put("#c23b22", to=(0, 0, 20, 20))
lbl = tk.Label(root); lbl.pack(padx=20, pady=20)

def bigger():
    lbl.img = base.zoom(4)        # keep the new image alive
    lbl.config(image=lbl.img)

bigger()
root.mainloop()
```

@@ tk.err2.recursion-update
Q: My window freezes or crashes when I call update() inside a loop or a callback
aka: update in loop, update causes recursion, while loop with update, update() bad, fatal python error tkinter
A: Calling `update()` inside callbacks can run **other** callbacks in the middle of yours (even the same one again), causing odd bugs or `RecursionError`. Replace `while` + `update()` loops with an `after` loop.
see: tk.update, tk.game-loop
```py bad
while running:
    move_player()
    root.update()          # re-enters event handlers; hard-to-find bugs
    time.sleep(0.016)
```
```py
import tkinter as tk

root = tk.Tk()
c = tk.Canvas(root, width=200, height=60, bg="white"); c.pack()
dot = c.create_oval(0, 20, 20, 40, fill="red")

def loop():
    c.move(dot, 3, 0)
    root.after(16, loop)
loop()
root.mainloop()
```
